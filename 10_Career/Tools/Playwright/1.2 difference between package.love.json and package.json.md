# Quick Notes: package.json vs. package-lock.json

### 1. `package.json` (The Intent / Manifest)
* **What it is:** High-level project blueprint maintained by you.
* **Core duties:**
  * Defines project metadata (name, version).
  * Stores test runner scripts (e.g., `"test": "playwright test"`).
  * Lists direct packages under `devDependencies` using flexible SemVer rules (`^` for minor updates, `~` for patch updates).
* **Rule:** You edit this file manually or via `npm install <package>`.

---

### 2. `package-lock.json` (The Exact State / Snapshot)
* **What it is:** Full, deterministic dependency tree generated automatically by NPM.
* **Core duties:**
  * Pins the exact version of every direct and sub-dependency (no `^` or `~`).
  * Stores cryptographic integrity hashes (`sha512-...`) to guarantee packages haven't been tampered with.
  * Ensures tests run on identical code across every machine and CI/CD runner.
* **Rule:** Never edit this file manually; NPM generates and updates it.

---

### 3. Cheat Sheet: When NPM Uses Which File

| Command | Files Used | What It Does | Best For |
| :--- | :--- | :--- | :--- |
| `npm install` | Both `package.json` & `package-lock.json` | Resolves ranges, downloads packages, and creates/updates the lockfile. | Local dev setup & adding new tools |
| `npm ci` | Strictly `package-lock.json` | Wipes `node_modules` and reinstalls exact pinned versions from lockfile. | CI/CD pipelines & clean team builds |
